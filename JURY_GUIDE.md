## 4 ключевых сценария для проверки жюри (Step-by-Step)

### Сценарий №1. Автоматический расчёт скоринга $\rightarrow$ Одобрение аналитиком $\rightarrow$ Выдача кредита
1. Откройте **[http://localhost:3000/login](http://localhost:3000/login)** и введите логин **`client1`** (или **`client6`**), пароль **`password123`**.
2. В дашборде нажмите **«Подать заявку на кредит»**:
   * Обратите внимание: ИНН `500100000011`, наименование ИП, ОГРНИП, дата регистрации и налоговый режим подтянулись автоматически из ЕГРИП.
   * Выберите: цель — *«Пополнение оборотных средств»*, сумма — *800 000 ₽*, срок — *12 месяцев*.
   * **Загрузка выписки:** прикрепите хорошую выписку [`test_statements/1_good_positive/DEMO-001_good_clean_revenue.csv`](file:///Users/cr1stal/Desktop/projects/AlphaHack/AlphaHack/test_statements/1_good_positive/DEMO-001_good_clean_revenue.csv). ML-парсер мгновенно рассчитает выручку ~8.7 млн ₽ и чистый операционный поток +4.9 млн ₽.
   * На шаге согласий обратите внимание на 3 независимых согласия (ПДн, БКИ, партнёры).
3. Нажмите **«Отправить заявку»**.
   * Заявка мгновенно просчитывается скоринговым движком: балл 100, $DSCR = 3.9$, ставка 18%.
   * По правилам кредитования заявка передаётся риск-аналитику банка (статус `review`).
4. Нажмите **«Выйти»** и войдите как **`analyst`** (пароль `password123`, ссылка [http://localhost:3000/employee/login](http://localhost:3000/employee/login)).
5. В очереди андеррайтинга откройте досье этой заявки:
   * Ознакомьтесь с блоком **AI-ассистент** (8 аналитических метрик: Скоринг, DSCR, NCF, Безопасный платёж, БКИ, Проверка ФНС/ЗСК).
   * На панели действий нажмите **«Одобрить оферту (T12)»**. Обратите внимание на **всплывающее модальное окно подтверждения**, защищающее от случайных кликов («Вы уверены, что хотите одобрить оферту?»).
   * Подтвердите действие: заявка переходит в статус `offer`.
6. Выйдите и снова войдите под **`client1`**:
   * В карточке заявки отображается готовая персональная оферта Альфа-Банка (18%, 12 мес, 73 344 ₽/мес).
   * Нажмите **«Принять предложение и получить деньги»**:
   * Заявка проходит статусы `accepted` $\rightarrow$ `signed_sim` (подписание ЭЦП) $\rightarrow$ `disbursed_sim` (зачисление средств на счёт предпринимателя с графиком платежей).

### Сценарий №4. Интерактивное дозапрашивание документов и диалог (T11 $\leftrightarrow$ T10)
1. Войдите как **`analyst`**, откройте заявку клиента в статусе `review`.
2. В блоке действий выберите **«Запросить сведения»**:
   * Укажите предмет запроса: *«Предоставьте, пожалуйста, пояснения по назначению платежей за ноябрь и договор аренды»*.
   * Заявка переходит в статус `need_info` (T11).
3. Войдите под клиентом:
   * Клиент видит яркий баннер **«Банк запросил дополнительную информацию»** с цитатой вопроса аналитика.
   * Нажимает **«Ответить на запрос банка»**, вводит поясняющий комментарий, прикрепляет файл и отправляет.
   * Заявка возвращается аналитику в работу (T10 $\rightarrow$ `review`).
4. Войдите как **`analyst`**:
   * В карточке заявки отображается история диалога: дата запроса, формулировка аналитика, ответ заёмщика и прикреплённый документ.
   * Аналитик может принять взвешенное решение об одобрении (T12).

---

### Сценарий №5. Запрос альтернативных условий клиентом $\rightarrow$ Встречное решение аналитика
1. На этапе сформированной оферты (`offer`) клиент нажимает кнопку **«Запросить другие условия»** в карточке предложения.
2. В модальном окне указывает желаемую сумму, срок, комфортный платёж и комментарий (например: *«Просим увеличить срок до 36 мес для снижения финансовой нагрузки»*).
3. Заявка переходит аналитику в статус `review`. Клиент видит статусное уведомление: *«Запрос на изменение условий отправлен кредитному аналитику»*.
4. В кабинете аналитика появляется плашка *«Встречный запрос от заёмщика»* с пожеланиями клиента и активными действиями:
   * **«Предложить другой вариант (T12)»**: открытие калькулятора параметров оферты и утверждение адаптированных условий;
   * **«Отказать (T13)»**: мотивированный отказ по заявке, если альтернативные условия не проходят по политике риска.

## Технологический стек решения

* **Frontend**: React 19, TypeScript, Vite, Tailwind CSS, Lucide Icons, React Router 7.
* **Backend**: .NET 10 (C#), ASP.NET Core Minimal APIs, Entity Framework Core, Wolverine (In-process Event Bus / CQRS), BCrypt.Net, JWT RS256.
* **Database**: PostgreSQL 16/17 (схемы `auth`, `client`, `bank_employee`, `synthetic`, `public`).
* **ML Service**: Python 3.11, FastAPI, Uvicorn, Scikit-learn, XGBoost, Tesseract OCR / PDF-parser.
* **Storage**: MinIO S3 (безопасное хранение договоров, выписок и спецификаций).
* **FSM (State Machine)**: строгий конечный автомат состояний T01–T28 со сквозным аудитом каждого перехода.

## Команды для локального развертывания (при необходимости)

Если требуется поднять сервисы локально с нуля:

```bash
# 1. Запуск БД и MinIO в Docker
docker compose up -d

# 2. Инициализация БД и пользователей
psql -U postgres -h localhost -d SmartKabinet -f backend/scripts/create_synthetic_tables.sql
psql -U postgres -h localhost -d SmartKabinet -f backend/scripts/seed_synthetic_data.sql
psql -U postgres -h localhost -d SmartKabinet -f backend/scripts/seed_users.sql

# 3. Запуск Backend (.NET 10)
cd backend
dotnet run --project SmartKabinet.Host/SmartKabinet.Host.csproj

# 4. Запуск Frontend
cd frontend
npm install
npm run dev
```
Клиентский интерфейс откроется по адресу: **`http://localhost:3000`**
