### Где и как загружать выписку

* **Через веб-интерфейс:** в кабинете клиента при заполнении заявки на шаге *«Финансовые показатели»* прикрепить CSV-файл в поле загрузки выписки. ML-сервис автоматически распарсит транзакции, выделит выручку, операционные расходы, платежи по кредитам и рассчитает чистый денежный поток (NCF).
* **Через REST API:** `POST /api/client/applications/{id}/statement` (Swagger: [http://localhost:5189/swagger](http://localhost:5189/swagger)).

### Сценарий 1. Сквозное прохождение заявки и выдача кредита

**Цепочка:** T01 $\rightarrow$ T03 $\rightarrow$ T07/T12 $\rightarrow$ T21 $\rightarrow$ T22 $\rightarrow$ T23  
*Суть:* клиент с чистой историей, стабильными оборотами и высоким скоринговым баллом получает оферту, утверждённую аналитиком, и проходит выдачу кредита.

1. Откройте **[http://localhost:3000/login](http://localhost:3000/login)** и войдите как **`client1`** (или **`client6`**), пароль **`password123`**. Альтернатива: зарегистрировать нового клиента по ИНН `990000000115` (ИП Иванов С.П.).
2. В дашборде нажмите **«Подать заявку на кредит»**:
   * Обратите внимание: ИНН `500100000011`, наименование ИП, ОГРНИП, дата регистрации и налоговый режим подтянулись автоматически из ЕГРИП.
   * Выберите: цель — *«Пополнение оборотных средств»*, сумма — *800 000 ₽*, срок — *12 месяцев*.
   * **Загрузка выписки:** прикрепите [`DEMO-001_good_clean_revenue.csv`](test_statements/1_good_positive/DEMO-001_good_clean_revenue.csv). ML-парсер мгновенно рассчитает выручку ~8.7 млн ₽ и чистый операционный поток +4.9 млн ₽.
   * На шаге согласий обратите внимание на 3 независимых согласия (ПДн, БКИ, партнёры).
3. Нажмите **«Отправить заявку»**:
   * Заявка мгновенно просчитывается скоринговым движком: балл **100 / 100**, $DSCR = 3.9$, ставка **18%**, расчётный платёж **73 344 ₽/мес**.
   * По правилам кредитования заявка передаётся риск-аналитику банка (статус `review`).
4. Нажмите **«Выйти»** и войдите как **`analyst`** ([http://localhost:3000/employee/login](http://localhost:3000/employee/login), пароль `password123`).
5. В очереди андеррайтинга откройте досье этой заявки:
   * Ознакомьтесь с блоком **AI-ассистент** (8 аналитических метрик: Скоринг, DSCR, NCF, Безопасный платёж, БКИ, Проверка ФНС/ЗСК).
   * На панели действий нажмите **«Одобрить оферту (T12)»**. Появится **модальное окно подтверждения**, защищающее от случайных кликов («Вы уверены, что хотите одобрить оферту?»).
   * Подтвердите действие: заявка переходит в статус `offer`.
6. Выйдите и снова войдите под **`client1`**:
   * В карточке заявки отображается готовая персональная оферта Альфа-Банка (18%, 12 мес, 73 344 ₽/мес).
   * Нажмите **«Принять предложение и получить деньги»**: заявка проходит статусы `accepted` (T21) $\rightarrow$ `signed_sim` (T22, подписание ЭЦП) $\rightarrow$ `disbursed_sim` (T23, зачисление средств на счёт с графиком платежей).

**Ожидаемый результат:** скоринг 100/100, ставка 18%, платёж 73 344 ₽; после одобрения аналитиком у клиента активна кнопка получения денег; цепочка акцепт → ЭЦП → выдача проходит полностью.

### Сценарий 2. Встречное предложение (counter-offer)

*Суть:* запрошенные сумма или срок создают слишком высокую нагрузку на NCF, но бизнес платежеспособен. Система не отказывает, а автоматически снижает риск, растягивая срок.

**Вариант А: покупка оборудования (`client2`)**

1. Войдите под **`client2`** (`password123`).
2. Создайте заявку на **«Покупку оборудования»**: стоимость `2 500 000 ₽`, собственный взнос `250 000 ₽` (10%), срок `24 месяца`.
3. Прикрепите выписку [`DEMO-002_good_equipment_supplier.csv`](test_statements/1_good_positive/DEMO-002_good_equipment_supplier.csv) или [`DEMO-003_good_steady_growth.csv`](test_statements/1_good_positive/DEMO-003_good_steady_growth.csv).

### Сценарий 4. Двусторонний диалог: дозапрос сведений

**Цепочка:** T11 $\leftrightarrow$ T04 $\rightarrow$ T10  
*Суть:* аналитику нужны разъяснения по выписке или дополнительные справки. Клиент видит уведомление, отвечает через личный кабинет, после чего заявка возвращается аналитику.

1. **В кабинете аналитика (`analyst`):**
   * откройте заявку клиента в статусе `review`;
   * в блоке действий выберите **«Запросить сведения»**;
   * введите вопрос, например: *«Предоставьте, пожалуйста, пояснения по назначению крупных списаний в пользу ООО Вектор за октябрь и подтверждающий договор»* (или: *«…по назначению платежей за ноябрь и договор аренды»*);
   * отправьте запрос: заявка переходит в статус `need_info` (T11).
2. **В кабинете клиента:**
   * вверху экрана появляется яркий баннер **«Банк запросил дополнительную информацию»**;
   * в карточке заявки отображается цитата вопроса аналитика;
   * нажмите **«Ответить на запрос банка»**, введите поясняющий комментарий, прикрепите документ и отправьте;
   * заявка возвращается в работу банка (T10 $\rightarrow$ `checking` / `review`).
3. **В кабинете аналитика:**
   * в карточке заявки отображается история диалога: дата запроса, формулировка аналитика, ответ заёмщика и ссылка на прикреплённый файл;
   * теперь аналитик может вынести обоснованное решение об одобрении (T12).

### Сценарий 6. Запрос альтернативных условий клиентом

*Суть:* клиент не согласен с условиями готовой оферты и просит другие; аналитик принимает встречное решение.

1. На этапе сформированной оферты (`offer`) клиент нажимает кнопку **«Запросить другие условия»** в карточке предложения.
2. В модальном окне указывает желаемую сумму, срок, комфортный платёж и комментарий (например: *«Просим увеличить срок до 36 мес для снижения финансовой нагрузки»*).

4. В кабинете аналитика появляется плашка **«Встречный запрос от заёмщика»** с пожеланиями клиента и действиями:
   * **«Предложить другой вариант (T12)»**: открытие калькулятора параметров оферты и утверждение адаптированных условий;
   * **«Отказать (T13)»**: мотивированный отказ, если альтернативные условия не проходят по политике риска.

## Локальное развёртывание и сброс данных

### 1. Запуск для жюри

В репозитории настроен полный стек контейнеров (`Frontend`, `Backend`, `ML-сервис`, `PostgreSQL 16` с предзаполненными данными и `MinIO`). Чтобы запустить всё, нужно перейти в корень проекта и запустить команду:

```bash
docker compose up --build
```

> **Автоматическая инициализация:** Контейнер базы данных при первом старте автоматически создаёт базы `SmartKabinet` и `SyntheticDb`, накатывает таблицы и заполняет их синтетическими данными ЕГРИП, ФНС, ЗСК и готовыми пользователями через скрипт `docker/postgres/init-dbs.sh`. Дополнительных ручных скриптов накатывать не нужно!

После запуска:
- **Интерфейс системы**: **[http://localhost:3000](http://localhost:3000)**
- **Swagger API**: **[http://localhost:5000/swagger](http://localhost:5000/swagger)**
- **ML FastAPI Docs**: **[http://localhost:8000/docs](http://localhost:8000/docs)**
- **MinIO Console**: **[http://localhost:9001](http://localhost:9001)** (`minioadmin` / `minioadmin`)

---

### 2. Запуск вручную для локальной разработки (без полного Docker-стека)

Если вы разрабатываете и хотите запускать сервисы отдельно:

```bash
# 1. Запуск БД и MinIO в Docker
docker compose up -d postgres minio

# 2. Инициализация БД и пользователей (при необходимости)
psql -U postgres -h localhost -p 5433 -d SmartKabinet -f backend/scripts/create_synthetic_tables.sql
psql -U postgres -h localhost -p 5433 -d SmartKabinet -f backend/scripts/seed_synthetic_data.sql
psql -U postgres -h localhost -p 5433 -d SmartKabinet -f backend/scripts/seed_users.sql

# 3. Запуск Backend (.NET 10)
cd backend
dotnet run --project SmartKabinet.Host/SmartKabinet.Host.csproj

# 4. Запуск Frontend
cd frontend
npm install
npm run dev
```

Клиентский интерфейс откроется по адресу: **`http://localhost:3000`**
