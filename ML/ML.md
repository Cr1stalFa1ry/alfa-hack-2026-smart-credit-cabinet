# ML.md — что делает код сейчас

*Обновлено 2026-10-21 · версия пайплайна 0.1.0*

## Схема

```
файл CSV/XLSX → parser → rules → (Qwen для «неясно», по желанию) → metrics → JSON
код причины → шаблон → (Qwen переписывает, проверки) → текст клиенту
```

| Модуль | Что делает |
|---|---|
| `app/parser.py` | Читает CSV в utf-8, cp1251 или utf-16 с разделителями `, ; \t \|`, а также XLSX. Строку заголовка ищет сам, поэтому шапка банковской выгрузки (счёт, период, остатки) пропускается. Строки «Итого/Остаток/Обороты» тоже. Понимает синонимы колонок (`Дата операции`, `Сумма`, `Назначение платежа`…) и пару Приход/Расход вместо `amount`. Суммы в форматах `1 234,56`, `−500`, `(300)`, даты `YYYY-MM-DD`, `DD.MM.YYYY`. Плохой файл → `StatementError(код)` |
| `app/rules.py` | Ключевые слова по назначению платежа с учётом знака: «Оплата по счёту» с плюсом — выручка, с минусом — расход. Сначала проверяются исключения (кредит, свои средства, возврат, налог), потом общие слова. Хвосты «Без налога (НДС)» и «в т.ч. НДС» вырезаются. Контрагент проверяется узким списком (УФК/ФНС → налог, маркетплейсы → выручка) |
| `app/classifier.py` | Правила, затем правило владельца: если `owner_name` (ФИО ИП из F01) совпал с контрагентом в «Иванов Иван Иванович», «Иванов И.И.» или «ИП Иванов И. И.», это свои средства. Потом Qwen, только для оставшихся `unclear` (уникальные, пачками, ФИО владельца тоже в промпте). Ответ модели проверяется по списку категорий и знаку суммы |
| `app/metrics.py` | Помесячная таблица и показатели (см. ниже) |
| `app/analyzer.py` | Собирает всё вместе. Любая проблема → `manual_input_required` + причина |
| `app/explain.py`, `templates.json` | Задача 2: шаблон, при наличии модели — переписывание с проверками |
| `app/cache.py`, `app/precompute.py` | Кэш результатов по sha256 файла и кэш ответов модели |
| `app/api.py` | FastAPI: `/v1/statement/analyze`, `/v1/explain`, `/health` |
| `eval/evaluate.py` | Задача 3: сверка с правильными ответами (±1%), плохие файлы, точность категорий |

**Категории:** `revenue`, `loan_in`, `own_transfer`, `refund`, `expense`, `loan_payment`, `tax`, `unclear`.

## Показатели (совпадают с полями листа «Данные»)

| Ключ ответа | Смысл | Как считаем |
|---|---|---|
| `avgMonthlyRevenueRub` | выручка/мес (F13 cleanReceipts) | среднее по месяцам суммы `revenue`. Кредиты, свои переводы и возвраты не входят |
| `avgMonthlyExpensesRub` | расходы/мес (F13 operatingOutflow) | `expense` + `tax`. Платежи по кредитам и свои переводы не входят |
| `avgMonthlyNetRub` | остаётся/мес (F33) | среднее(выручка − расходы), может быть < 0 |
| `avgMonthlyLoanPaymentsRub` | платежи по кредитам/мес | `loan_payment`: тело, проценты, лизинг |
| `revenueCV` | скачки выручки (F38) | σ генеральной / среднее; ≤0,3 — стабильно, >0,6 — сильно скачет |
| `monthsCount` | месяцев данных (F32) | закрытые месяцы от первого до последнего (максимум 12 последних) |
| `annualRevenueRub` | выручка за год (F37) | только при ровно 12 мес., без экстраполяции |
| `avgMonthlyTaxesRub`, `loanProceedsTotalRub` | справочно | — |

Каждый показатель приходит в виде `{value, status: ok|not_found|unclear, display, note}`. Если ничего не нашли, ставим `value=null` и `display` «не найдено» или «неясно» — **никогда 0**. Месяц, не закрытый на дату `as_of` (F27), не учитывается. Месяц без операций внутри периода считается нулём, и об этом пишется предупреждение. В ответ также входят `monthly` (помесячная таблица, готовая для F13), `classification` (сколько строк поняли правила или модель, топ-20 непонятых) и `warnings`.

**«Нужен ручной ввод»** (`status=manual_input_required`, `reason.code`): `EMPTY_FILE`, `UNREADABLE` (битый файл или больше 20% строк без даты и суммы), `MISSING_COLUMNS`, `SHORT_HISTORY` (меньше 3 закрытых мес.), `TOO_MANY_UNCLEAR` (не поняли больше 50% поступлений), `FILE_TOO_LARGE`.

## Открытые вопросы (согласовать)

- **Data:** формат CSV, знак суммы, кодировка; включаем ли незакрытый месяц; что делать с частичным первым месяцем; лимит 12 мес.; входят ли налоги в расходы (сейчас входят).
- **Data/БА:** возврат покупателю (−) сейчас не считается ни расходом, ни уменьшением выручки, а показывается отдельно (`refunds_out`); лизинг сейчас отнесён к платежам по кредиту.
- **БА:** 20 размеченных строк → в `data/labeled/descriptions.csv` и в few-shot (`classifier.FEW_SHOT`).
- **Аналитик (Лера):** тексты шаблонов → `app/templates.json` (сейчас там черновик ML по кодам листа «Правила»).
- **Backend:** контракт ответа (camelCase как в словаре данных), передача `as_of` и `owner_name`.
