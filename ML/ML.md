Что делает код, API, контракт и метрики описаны в [README.md](README.md). Здесь — только статус и то, что нужно согласовать.

## Схема

```
счёт / КП / выписка (PDF, скан, фото) → pages (текстовый слой | Tesseract) → invoice | statement_pdf → проверки → JSON
выписка CSV/XLSX → parser ─┐
выписка PDF/скан ──────────┴→ rules → (Qwen для «неясно», по желанию) → metrics → analysis
код причины → шаблон → (Qwen переписывает, проверки) → текст клиенту
```

## Открытые вопросы

- **Backend — формат ответа `/v1/documents/read`.** Предложение — в README («Контракт»). Нужно подтвердить поля `document`, `run`, коды `issues`, единицы `bbox` (пункты PDF).
- **Backend — исправить в `MlServiceClient`:**
  1. `as_of` и `owner_name` уходят полями формы. ML теперь понимает и форму, и query, но в старой версии ML они терялись.
  2. `GetDecimal` превращает `null` в `0m` — неизвестное значение становится нулём.
  3. Content-Type для PDF/JPG выставляется как `text/csv`: ML это не мешает, но вводит в заблуждение.
- **Backend:** где хранить результаты по версиям файлов. Кто и как передаёт `expected_sha256`. Сравнение со стоимостью покупки (`equipment_price`), а не с кредитом.
- **Data/БА:** нужен новый отложенный набор документов (другие бланки поставщиков, реальные сканы и фото телефоном). Эталон для `test_account_id` не нужен: это служебная метка макета.
- **БА:** правило для «личного», которое не доказать текстом («покупка ПЯТЕРОЧКА», «ЖКУ»). Сейчас это `personal` + сотрудник.
- **Аналитик (Лера):** тексты шаблонов → `app/templates.json` (пока черновик ML).
