# ML-сервис: чтение документов анкеты, анализ выписки, объяснение решения

Сервис делает три вещи:

1. **Читает документы кредитной анкеты.** Это счета и коммерческие предложения (КП), а также банковские выписки. Форматы: PDF с текстом, сканы, фото JPG/PNG/TIFF, CSV и XLSX. Из счёта и КП извлекаются номер, дата, поставщик и покупатель с ИНН, позиции и итог. Из выписки — шапка и каждая операция с категорией. У каждого важного значения есть страница, исходный фрагмент и координаты. Неизвестное значение возвращается как `null`, а не как 0 или догадка. Сомнительные случаи помечаются для сотрудника.
2. **Считает показатели выписки**: выручку, расходы, кредитную нагрузку, стабильность — за закрытые месяцы.
3. **Объясняет решение клиенту**: код причины превращается в 2–3 понятных предложения.

Кредитное решение и ставку сервис **не определяет**: это скоринг по правилам на бэкенде. Сравнение прочитанного с заявкой и реестрами, хранение версий файлов и повторный скоринг тоже делает бэкенд. Большие модели для чтения документов не нужны: текстовый слой PDF + Tesseract OCR + правила. Qwen по желанию помогает только с непонятными операциями выписки и с текстом объяснения.

## Запуск

```bash
# Docker, без нейросети (правила + шаблоны + Tesseract внутри образа)
docker compose up --build ml                 # http://localhost:8000/docs

# Docker + Ollama с Qwen2.5 7B (первый запуск скачает модель ~4.7 ГБ)
docker compose --profile llm up --build

# Локально (Python 3.13). Для сканов и фото нужен Tesseract с русским языком:
#   Debian/Ubuntu: apt install tesseract-ocr tesseract-ocr-rus;  macOS: brew install tesseract tesseract-lang;
#   Windows: установщик UB Mannheim (путь C:\Program Files\Tesseract-OCR находится сам).
python3.13 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.api:app --port 8000
.venv/bin/python -m pytest -q                         # тесты (OCR-тесты пропускаются, если Tesseract не установлен)
.venv/bin/python -m app.documents файл.pdf --as-of 2026-10-24   # прочитать один документ → JSON
.venv/bin/python -m eval.documents [--split development]        # чтение документов против эталона → eval/documents_report.*
.venv/bin/python -m eval.evaluate [--llm]                       # выписки, плохие файлы, категории → eval/report.json
.venv/bin/python -m app.precompute data/demo/*.csv --as-of 2026-10-21   # прогрев кэша для демо
```

Без Tesseract сервис работает: PDF с текстовым слоем, CSV и XLSX читаются как обычно, а страница-скан получает проблему `OCR_UNAVAILABLE` и уходит сотруднику.

## API

| Метод | Что делает |
|---|---|
| `POST /v1/documents/read` (multipart `file` + поля формы, см. контракт ниже) | чтение счёта, КП или выписки → поля, позиции, операции, проблемы, статус |
| `POST /v1/statement/analyze` (multipart `file`; `as_of`, `owner_name` — в query **или полями формы**; `use_llm`, `include_transactions`) | показатели выписки или `manual_input_required` с причиной. Принимает CSV/XLSX и PDF/скан/фото; последние идут через тот же разбор, что `/v1/documents/read` |
| `POST /v1/explain` `{reason_codes, decision, context}` | текст для клиента: `source` = `llm` / `template` / `generic` |
| `GET /health`, `GET /v1/categories` | состояние сервиса, нейросети и OCR (`ocr: true/false`); список категорий |

Полная схема лежит в `docs/openapi.json`, Swagger — на `/docs`. Примеры ответов: `docs/examples/*.json` — счёт, неполный счёт, скан счёта и выписка на 145 операций.

## Контракт `/v1/documents/read` (предложение для бэкенда)

**Запрос**: `multipart/form-data`.

| Поле | Обязательно | Смысл |
|---|---|---|
| `file` | да | PDF, JPG/PNG/TIFF, CSV, XLSX; до 20 МБ и до 30 страниц |
| `document_id`, `document_version`, `run_id` | нет | ID документа, версии файла и запуска в бэкенде — возвращаются как есть в `document` и `run` |
| `expected_sha256` | нет | sha256 версии файла по данным бэкенда. Не совпал с полученными байтами → `status=FAILED`, `FILE_VERSION_MISMATCH` |
| `as_of` | нет | дата рассмотрения для показателей выписки (по умолчанию сегодня) |
| `owner_name` | нет | ФИО владельца ИП: переводы от или на его имя — свои средства. Если не передано, берётся владелец из шапки выписки |
| `use_llm` | нет | спрашивать Qwen о непонятых операциях выписки (по умолчанию `true`; без Ollama не используется) |

**Ответ** (JSON):

| Поле | Смысл |
|---|---|
| `document` | `{document_id, document_version, sha256}` — к какой версии файла относится результат |
| `run` | `{run_id, processed_at}` |
| `schema_version`, `pipeline_version` | `documents-1`, `0.2.0` |
| `file` | `{sha256, bytes, name, format: pdf/image/table, pages, pages_declared}`; `pages_declared` — из «Страница X из Y» |
| `document_type` | `INVOICE` / `COMMERCIAL_OFFER` / `BANK_STATEMENT` / `UNKNOWN` |
| `status` | `EXTRACTED` — прочитан полностью; `PARTIAL` — не хватает страниц; `NEEDS_REVIEW` — плохое качество, конфликт, нет критического поля, не сошлись обороты; `FAILED` — не прочитан |
| `needs_review` | `true`, если есть хоть одна проблема, в том числе отдельные операции выписки для проверки |
| `fields` | поля документа (см. ниже) |
| `line_items` | только счёт и КП: `{description, quantity, unit, unit_price_rub, amount_rub, page, quote, bbox, confidence}` |
| `transactions` | только выписка: `{row, date, amount (со знаком), counterparty, description, category, category_ru, source: rules/llm/none, needs_review, page, quote, bbox, confidence}` |
| `analysis` | только выписка: ответ в формате `/v1/statement/analyze` (показатели или `manual_input_required`). Считается только при `status=EXTRACTED` |
| `issues` | `[{code, message, page?, pages?, field?}]` — почему нужен сотрудник |
| `pages` | `[{page, text_source: text/ocr/ocr_unavailable, dpi, ocr_confidence}]` |
| `cached` | результат взят из кэша по sha256 файла |

**Поле** — `{value, status: ok | not_found | unclear, page, quote, bbox, confidence, note?}`. `quote` — исходный фрагмент документа, `bbox` — `[x0, top, x1, bottom]` в пунктах PDF от левого верхнего угла страницы. `confidence` — уверенность OCR 0..1 по словам значения. Для текстового слоя она `null`: выдуманную уверенность не ставим. Значение с уверенностью OCR ниже 0,6 или со страницы ниже 100 dpi возвращается как `value=null, status=unclear`, а `quote` остаётся для сотрудника.

- Счёт и КП: `document_number`, `document_date`, `supplier_name`, `supplier_inn`, `buyer_name`, `buyer_inn`, `total_amount_rub`.
- Выписка (PDF): `account_holder_name`, `account_holder_inn`, `period_from`, `period_to`, `account_number` (20 цифр), `credit_total_rub`, `debit_total_rub`, `opening_balance_rub`, `closing_balance_rub`. Начальный остаток — только для сверки, не как подтверждённый резерв.

**Коды проблем** (`issues[].code`):

| Код | Что значит | Статус |
|---|---|---|
| `MISSING_PAGE` | «Страница 1 из 2», а передана одна | `PARTIAL` |
| `LOW_RESOLUTION`, `OCR_UNAVAILABLE`, `EMPTY_PAGE` | скан ниже 100 dpi; нет OCR; пустая страница | `NEEDS_REVIEW` |
| `FIELD_NOT_FOUND`, `FIELD_UNCLEAR`, `FIELD_CONFLICT` | нет ИНН сторон или итога; прочитано неуверенно (в т.ч. ИНН с неверным контрольным числом); на страницах разные значения | `NEEDS_REVIEW` |
| `ITEMS_TOTAL_MISMATCH`, `ITEM_PRICES_MISSING` | сумма позиций ≠ итогу; у позиций нет цен | `NEEDS_REVIEW` |
| `TOTALS_MISMATCH`, `BALANCE_MISMATCH`, `ROW_NUMBER_GAP`, `PERIOD_NOT_COVERED`, `AMOUNT_SIGN_UNKNOWN`, `TABLE_NOT_FOUND` | обороты в шапке ≠ сумме операций; остатки не сходятся; пропуск в нумерации строк; операции покрывают не весь период; не прочитан знак суммы; нет таблицы операций | `NEEDS_REVIEW` |
| `TRANSACTIONS_NEED_REVIEW` | отдельные операции неоднозначны («покупка ПЯТЕРОЧКА», «ЖКУ», непонятное поступление) | статус не меняется, `needs_review=true` |
| `UNKNOWN_DOCUMENT_TYPE` | не счёт, не КП и не выписка | `NEEDS_REVIEW` |
| `UNSUPPORTED_FORMAT`, `UNREADABLE`, `TOO_MANY_PAGES`, `FILE_TOO_LARGE`, `FILE_VERSION_MISMATCH`, коды чтения CSV (`EMPTY_FILE`, `MISSING_COLUMNS`…) | файл не прочитан | `FAILED` |

**Что ожидается от бэкенда:**

- Брать `value` только при `status=ok`. `null` — это «неизвестно», а не 0. Сейчас `MlServiceClient.GetDecimal` превращает `null` в `0m` — это нужно исправить.
- Сравнивать сумму счёта со **стоимостью покупки** (`equipment_price`), а не с суммой кредита. Покупатель и поставщик сравниваются по ИНН. Расхождение (`AMOUNT_MISMATCH`, `BUYER_MISMATCH`, `SUPPLIER_MISMATCH`) — повод для уточнения, а не автоматический признак мошенничества.
- Хранить результат по `(document_id, document_version, document.sha256)`. После замены файла старый результат не применять: новая версия → новый запрос. Если `sha256` результата ≠ sha256 текущей версии, результат отбрасывается. Кэш ML тоже ключуется по sha256, поэтому результат старого файла к новому не попадёт. Передавайте `expected_sha256`, тогда ML сам откажет на чужих байтах.
- Паспорта и документы на недвижимость — пока только ручная проверка: сервис их не читает.

## Как читаем документы

| Модуль | Что делает |
|---|---|
| `app/pages.py` | Страницы → слова с координатами. Текстовый слой PDF читает pdfplumber. Страница без текста (меньше 20 символов) и картинка проходят OCR Tesseract: `rus`, `--psm 6`, растр приводится к 300 dpi, страницы распознаются параллельно. С `rus+eng` движок путал кириллицу с похожей латиницей. Разрешение скана считается по встроенной картинке (пиксели / размер страницы), для фото без DPI предполагается лист A4. `reread()` заново распознаёт фрагмент строки как одну строку в масштабах 150/200/250 dpi |
| `app/fields.py` | Общее: поле с источником, суммы (`3 431 000,00`, `1.984.000,00`, `126 747 ,84` от OCR; дата и «3431 000.00» суммой не считаются), даты, **ИНН с проверкой контрольного числа**, колонки таблиц по строке заголовка. Если ИНН со скана не прошёл проверку, его цифры перечитываются; значение принимается, только если два перечитывания совпали и контрольное число верно |
| `app/invoice.py` | Счёт и КП. Стороны находятся по подписям («Поставщик», «ИНН покупателя», «Получатель предложения / Покупатель») — в ячейке, правее на той же строке и ниже в той же колонке. Позиции берутся из таблицы «Наименование / Кол-во / Цена / Сумма» или из бланка без таблицы («Оборудование», «Стоимость за единицу»). Позиции с разных страниц склеиваются по названию: состав на стр. 1, цены на стр. 2. Итог — общий («к оплате», «итоговая стоимость»), без подытогов и НДС. Доставка заново не прибавляется: итог сверяется с суммой позиций |
| `app/statement_pdf.py` | Выписка из PDF, скана или фото. Колонки определяются по заголовку таблицы, порядок любой: «Сумма» со знаком или «Приход/Расход». Операция начинается со строки с датой, перенос назначения приклеивается к ней. Из шапки берутся владелец, ИНН, период, обороты и остатки. Сверки: обороты = сумма операций, остатки, нумерация строк, покрытие периода |
| `app/documents.py` | Сборка: тип документа, нехватка страниц («Страница X из Y»), низкое разрешение, статус, маскирование неуверенных значений. Операции выписки идут в общий анализатор (`analyzer.analyze_transactions`). CLI: `python -m app.documents файл` |
| `app/parser.py`, `rules.py`, `classifier.py`, `metrics.py`, `analyzer.py` | Анализ выписки (см. ниже); CSV и XLSX читает `parser.py` |
| `app/explain.py`, `templates.json`, `llm.py`, `cache.py`, `precompute.py`, `api.py` | Объяснение решения, клиент Ollama, кэш по sha256, прогрев демо, HTTP |

## Анализ выписки

Операции классифицируются правилами по назначению с учётом знака: «Оплата по счёту» с плюсом — выручка, с минусом — расход. Сначала проверяются исключения: кредит, лизинг, свои средства, депозит, возврат, налог, личное. Затем — общие слова, включая сокращения выгрузок («Опл.», «Поступл. от покупателя», «Погаш. ссуды»). Контрагент проверяется узким списком (УФК/ФНС, маркетплейсы). Перевод от или на ФИО владельца — свои средства. Qwen, если включён, видит только оставшиеся непонятыми строки; его ответ проверяется по списку категорий и знаку суммы.

| Категория | Код пакета банка | В расчёте |
|---|---|---|
| `revenue` выручка | `BUSINESS_RECEIPT` | выручка |
| `expense` операционный расход, `tax` налог/взнос | `OPERATING_OUTFLOW` | расходы бизнеса (налоги входят) |
| `loan_in` кредит/заём | `LOAN_IN` | **не выручка**, справочно |
| `loan_payment` платёж по кредиту/лизингу | `LOAN_PAYMENT` | кредитная нагрузка, не расход |
| `own_transfer` свои средства (в т.ч. депозит) | `OWN_TRANSFER` | **не выручка и не расход** |
| `refund` возврат | `REFUND_IN` / `REFUND_OUT` | **не выручка**, отдельно |
| `personal` личный расход | `PERSONAL` | не расход бизнеса |
| `unclear` неясно | — | не выручка, на проверку |

**На проверку сотруднику** (`needs_review`) уходят: непонятые операции, категории от нейросети и личное, которое не доказать одним текстом (покупки в магазинах и аптеках, ЖКУ/ЖКХ без признака бизнес-помещения). Для них категория `personal` ставится, но окончательное решение — за человеком.

**Показатели** (поля листа «Данные»): `avgMonthlyRevenueRub` — выручка/мес (F13); `avgMonthlyExpensesRub` — расходы/мес (F13, с налогами); `avgMonthlyNetRub` — чистый поток (F33); `avgMonthlyLoanPaymentsRub` — платежи по кредитам и лизингу; `revenueCV` — σ/среднее (F38); `monthsCount` — закрытые месяцы, максимум 12 (F32); `annualRevenueRub` — только при 12 месяцах (F37); справочно `avgMonthlyTaxesRub`, `loanProceedsTotalRub`. Каждый показатель приходит как `{value, status, display, note}`; ничего не нашли — `value=null`. Незакрытый месяц на дату `as_of` не учитывается. Помесячная таблица `monthly` содержит, кроме прочего, колонку `personal`.

**«Нужен ручной ввод»** (`manual_input_required`): `EMPTY_FILE`, `UNREADABLE`, `MISSING_COLUMNS`, `SHORT_HISTORY` (меньше 3 закрытых месяцев), `TOO_MANY_UNCLEAR` (не поняли больше 50% поступлений), `FILE_TOO_LARGE`. Для PDF добавляются `NOT_A_STATEMENT` и любой блокирующий код из `issues` (`MISSING_PAGE`, `TOTALS_MISMATCH`…): по неполной или неуверенно прочитанной выписке показатели не считаются, но операции с категориями всё равно возвращаются.

\* Документы Макарова (M53, шаблон D) и выписка Соловьёва (S03, формат F, с 9-страничным сканом) прогнаны **один раз** на зафиксированном коде, до первого просмотра — `eval/documents_report_blind.md`. Найденные пробелы закрыты общими правками: подпись «Получатель предложения / Покупатель», суммы «1.984.000,00», пробел перед копейками от OCR, перечитывание только цифр ИНН. После этого M53 и S03 **больше не независимая проверка**: для следующей оценки нужен новый набор.

- 11 `null` — это намеренно размытый скан (35 dpi): `LOW_RESOLUTION`, значения сверяет сотрудник.
- 2 неверных значения — номера документов со сканов: «СЧ-S11-01» прочитан как «СЧ-511-01», латинская «M» — как кириллическая «М». OCR с языком `rus` не различает такие символы. Номер в решении не участвует; на такие поля ставится `note` с предупреждением.
- На фото первой страницы выписки латинские номера договоров (`DEBT-S1-A`) читаются кириллицей. На категорию это не влияет.

| `OCR_LANG`, `OCR_PSM`, `OCR_DPI` | `rus`, `6`, `300` | язык, режим разметки и разрешение OCR |
| `OCR_WORKERS`, `OCR_TIMEOUT_S` | `4`, `60` | параллельных страниц OCR, таймаут страницы |
| `DOC_MAX_PAGES` | `30` | максимум страниц в документе |

## Модель и нейросеть

- **OCR:** Tesseract 5 (Apache 2.0) с `rus.traineddata`, без дообучения. Скан A4 — около 1–1,5 с на страницу. Выписка на 9 страниц — около 5 с, повторно — мгновенно из кэша.
- **Нейросеть (необязательно):** [Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) через [Ollama](https://ollama.com). Используется только для (1) операций выписки, которые не поняли правила: строгий JSON с `enum` категорий, `temperature=0`; (2) переписывания шаблона объяснения с проверками (нет новых чисел, нет «одобрено» без одобрения, сохранён следующий шаг). Недоступна — работают правила и шаблоны. Чтение счетов и выписок от нейросети не зависит.

## Данные

- `data/demo`, `data/bad`, `data/labeled` — синтетика ML: демо-выписки, плохие файлы, размеченные строки.
- `data/package` — из пакета банка `ip_credit_ml_labeled_package`: 72 выписки `statements/DEMO-*.csv`, `monthly_facts.csv`, `statement_lines_control.csv`.
- `data/documents` — пакет «ML — документы и эталоны пяти ИП»: входы в `documents/`, эталоны в `labels/` (`documents_ground_truth.json`, `DEMO-001/003_transactions.json`, `splits.json`). Эталоны служат только для оценки и сервису на вход не подаются.
- Из пакета банка **не используются** в сервисе: модель кредитного решения (`applications`, `decisions_*` — решение принимают правила на бэкенде); автозаполнение по ИНН и проверки реестров (ЕГРИП, ЕФРСБ, блокировки ФНС, ЗСК — их уже делает бэкенд из `registry/*.csv`); антифрод и экономические отчёты.
- Все данные синтетические, ИНН тестовые. Внешних интеграций нет.
